# 消防器材总动员 - 场景匹配题实现计划

将游戏改为**科普答题类**：场景匹配题（根据场景选器材）。按本计划可实现「出题 → 选答 → 反馈 → 下一题 → 结算」的完整流程。

---

## 一、题目数据结构

在 `types.ts` 中新增题目类型与题目列表：

```ts
/** 单道题目：题干（场景）、四个选项（器材 id）、正确答案 id、解析 */
export interface QuizQuestion {
  id: number
  scenario: string   // 题干，如「锂离子电池生产车间/仓库 应配置哪种器材？」
  optionIds: [number, number, number, number]  // 四个选项对应的 EQUIPMENT id，含一个正确答案
  correctId: number  // 正确答案的器材 id（必须在 optionIds 中）
  explanation: string  // 选对/选错后展示的解析（可简要说明为何选该器材）
}
```

- **选项顺序**：题目数据里 `optionIds` 可固定顺序，**展示前对数组做一次随机打乱**（打乱索引），避免答案总在固定位置。
- **题目来源**：基于现有 4 种器材，每器材至少 1 题。题干用「配置场景」描述，问「应配置哪种器材？」。例如：
  - 题干：「微型消防站、重点防火区域、储能电站 应配置哪种器材？」→ 选项含 4 种器材名 → 正确答案：移动排烟风机。
- 建议题目数 **5～8 题**，部分器材可出 2 题（换不同问法或侧重目的/场景）。

## 三、状态设计（gameStore）

在现有 store 上增加/调整字段与方法：

| 字段 / 方法 | 类型 / 说明 |
|-------------|-------------|
| `currentIndex` | number，当前题目下标（0 起） |
| `score` | number，答对题数 |
| `userAnswer` | number \| null，当前题用户所选器材 id，null 表示未选 |
| `showResult` | boolean，当前题是否已选并需显示对错与解析 |
| `startQuiz()` | 进入答题：screen='play'，currentIndex=0，score=0，userAnswer=null，showResult=false |
| `submitAnswer(equipmentId: number)` | 记录 userAnswer，置 showResult=true；若答对则 score++ |
| `nextQuestion()` | currentIndex++，userAnswer=null，showResult=false；若无下一题则 screen='end' |
| `finish()` | 直接进入结束页（保留，用于提前结束或异常） |
| `restart()` | 回到开始页，重置所有答题状态 |

- 结束条件：`currentIndex >= QUESTIONS.length` 时进入结束页；结束页展示「答对 x / 总题数」与一句总结。

## 四、界面与流程

1. **开始页**  
   - 标题、简短说明（可改为「根据场景选出应配置的消防器材」）、按钮「开始答题」。

2. **答题页（play）**  
   - **未选时**：显示题干（`QUESTIONS[currentIndex].scenario`）、4 个选项（按 `optionIds` 打乱后的顺序展示器材名称）；点击某一选项即调用 `submitAnswer(选中的器材 id)`。
   - **已选时（showResult）**：  
     - 显示「正确」或「错误」、解析文案；  
     - 可选高亮正确选项、将错误选项置灰；  
     - 底部按钮「下一题」：调用 `nextQuestion()`；若已是最后一题，按钮文案可为「查看结果」，点击后进入结束页。

3. **结束页**  
   - 展示「答对 x / 总题数」、正确率或一句评语；按钮「再玩一次」调用 `restart()`。

## 六、实现顺序建议

1. **数据**：在 `types.ts` 中定义 `QuizQuestion` 和至少 5 道 `QUESTIONS`（题干、optionIds、correctId、explanation）。  
2. **选项打乱**：写一个 `shuffleOptions(optionIds)`，返回打乱后的 id 数组，用于当题展示；保证每题进入时只打乱一次（可在组件内 useMemo 依赖 currentIndex）。  
3. **Store**：按第三节实现/扩展 gameStore。  
4. **答题页 UI**：先实现「未选 → 选一项 → 显示对错+解析 → 下一题」单题流程，再接多题与结束页。  
5. **结束页**：展示 score / total，再玩一次。  
6. **样式与规则文档**：按清单收尾并更新规则说明。
