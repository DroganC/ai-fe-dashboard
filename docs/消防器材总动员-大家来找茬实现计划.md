# 消防器材总动员 - 大家来找茬实现计划

将游戏改为**大家来找茬**玩法：左右两幅图，找出若干处差异，点击正确区域即标记并得分，全部找完过关。可结合消防/安全场景出题（如车间、仓库、办公室的两图差异）。

---

## 一、玩法定义

1. **关卡**：每关为一组「左图 + 右图」，两图几乎相同，存在 **N 处差异**（通常 5～7 处）。
2. **操作**：用户在左图或右图上**点击**认为有差异的位置；若点击落在某一处差异的判定区域内，则该处视为**已找到**（高亮/打勾），并计入已找数量。
3. **胜利**：本关所有差异都找到后，进入「本关通过」；可进入下一关或结束页（展示总关数、总找茬数等）。
4. **容错**：可限制**错误点击次数**（如每关最多 5 次误点）或不做限制，仅做正确点击反馈。

---

## 二、整体规则细节（供规则文档与实现对齐）

以下规则已合并入 `src/games/fire-equipment-rally/docs/消防找茬.md`，实现时需一致。

### 2.1 游戏目标

- 在限定关卡内，找出每关左右两图中的全部差异；全部找对即过关，多关连续完成则进入结束页并展示统计。

### 2.2 屏幕与流程

| 屏幕 | 说明 | 出口 |
|------|------|------|
| 开始页 | 标题、玩法说明、开始按钮 | 点击「开始游戏」→ 找茬页（第 1 关） |
| 找茬页 | 左图 + 右图、进度、已找到高亮、可选误点提示 | 本关全部找完 → 本关通过；下一关 / 查看结果；误点超限（若启用）→ 本关失败提示 |
| 本关通过 | 弹层或内嵌提示「本关通过」+ 下一关 / 查看结果按钮 | 下一关 → 找茬页（下一关）；查看结果 → 结束页 |
| 结束页 | 总关数、总找茬数、再玩一次 | 再玩一次 → 开始页 |

### 2.3 单关规则

- **差异数量**：每关固定 N 处（建议 5～7 处），由关卡数据 `differences.length` 决定。
- **点击判定**：仅当点击落在某处**未找到**的差异的判定圆内时，记为命中；命中后该处立即标记为已找到，并在图上高亮（圆圈或勾）。
- **左右图独立**：点击左图时用该差异的 `left` 坐标判定，点击右图时用 `right` 坐标判定；同一处差异在左或右任一侧命中一次即算找到。
- **重复点击**：已找到的差异不再参与判定，用户重复点击已找区域不扣误点、不重复计数。
- **错误点击**：点击未命中任何未找到的差异时，记为一次错误点击；若启用「每关最大误点次数」（如 5 次），则达到上限后可弹出「本关失败」或仅禁止继续点击直到本关通过/重试，具体策略在 constants 中配置。

### 2.4 胜负与统计

- **本关胜利**：当前关所有差异均被找到（`foundIds` 覆盖本关全部 difference id）。
- **本关失败**（可选）：仅当启用误点上限时，错误点击达到上限且尚未找齐则本关失败；可提供「重试本关」或「返回开始」。
- **结束页统计**：总关卡数、通过的关卡数、总找茬数（所有关找到的差异总数）；可扩展正确率、总误点等。

### 2.5 提示与可选规则

- **提示**（可选）：每关提供有限次提示（如 1～2 次），使用后短暂高亮一处未找到的差异，不自动记为找到，不扣误点。
- **无时间限制**：首版不做倒计时，用户可无限时找茬；后续可加「每关限时」作为可选增强。

## 三、数据结构

### 3.1 差异区域（单处）

用**相对比例**描述位置，便于不同屏幕尺寸下复用同一套数据：

```ts
/** 一处差异的判定区域（相对图片宽高的比例 0～1） */
export interface DifferenceRegion {
  id: number
  /** 左图上该差异的区域：用圆表示时 (cx, cy, r) 均为 0～1 比例 */
  left:  { cx: number; cy: number; r: number }
  /** 右图上该差异的区域（同上） */
  right: { cx: number; cy: number; r: number }
}
```

- `cx, cy`：圆心在图片中的相对位置（0～1）。
- `r`：圆的半径（相对图片短边的比例，0～1），点击落在圆内即判定命中。
- 若后续要矩形区域，可改为 `left: { x: number; y: number; w: number; h: number }`（均为 0～1）。

### 3.2 单关数据

```ts
export interface SpotDifferenceLevel {
  id: number
  title: string
  /** 左图 URL（或静态资源路径） */
  leftImage: string
  /** 右图 URL */
  rightImage: string
  /** 本关所有差异（5～7 处为宜） */
  differences: DifferenceRegion[]
}
```

### 3.3 关卡列表

在 `types.ts`（或单独 `levels.ts`）中导出关卡数组：

```ts
export const SPOT_LEVELS: SpotDifferenceLevel[] = [
  {
    id: 0,
    title: '消防通道',
    leftImage: '/games/fer/level0-left.png',
    rightImage: '/games/fer/level0-right.png',
    differences: [
      { id: 0, left: { cx: 0.2, cy: 0.3, r: 0.05 }, right: { cx: 0.2, cy: 0.3, r: 0.05 } }, // 示例
      // ...
    ],
  },
  // 更多关卡
]
```

- 差异的 `left` / `right` 坐标可以不同（经典找茬是左右图各有一处对应差异）；若做「左右同一位置点击一次即算找到」，可左右用相同坐标，点击时同时检测左右两张图的点击。

## 四、状态设计（gameStore）

| 字段 / 方法 | 类型 / 说明 |
|-------------|-------------|
| `screen` | `'start' \| 'play' \| 'end'`，与现有一致 |
| `currentLevelIndex` | number，当前关卡下标（0 起） |
| `foundIds` | Set<number> 或 number[]，当前关已找到的差异 id 集合 |
| `wrongClicks` | number（可选），当前关错误点击次数，用于限制或仅做提示 |
| `start()` | 进入游戏：screen='play'，currentLevelIndex=0，清空 foundIds、wrongClicks |
| `markFound(differenceId: number)` | 将 differenceId 加入 foundIds |
| `recordWrongClick()` | wrongClicks++（若启用限制） |
| `isFound(differenceId: number)` | 是否已找到该差异 |
| `isLevelComplete()` | 当前关 differences 是否全部在 foundIds 中 |
| `nextLevel()` | currentLevelIndex++，清空 foundIds、wrongClicks；若无下一关则 screen='end' |
| `finish()` | 直接 screen='end' |
| `restart()` | screen='start'，重置所有状态 |

## 五、交互与流程

1. **开始页**  
   标题 + 说明（如「找出左右两图的差异，点击即可标记」）+ 按钮「开始游戏」。

2. **找茬页（play）**  
   - **布局**：左图、右图并排（移动端可上下排列），图片等比缩放、可滚动，保证坐标比例一致。
   - **状态展示**：当前第几关、本关进度「已找 x / 总数」、可选错误次数「剩余误点 x」。
   - **点击逻辑**：  
     - 用户点击**左图**或**右图**时，将点击位置转换为**相对该图的 (cx, cy)**（0～1）。  
     - 遍历当前关 `differences` 中未找到的项，判断 (cx, cy) 是否落在对应 `left` 或 `right` 的圆内（根据点击的是左图还是右图）。  
     - 若命中：调用 `markFound(differenceId)`，可选震动/音效；若未命中：`recordWrongClick()` 并可选 Toast 提示。
   - **已找到的差异**：在图上用半透明圆圈或勾号覆盖标出，避免重复点击。
   - **本关完成**：当 `isLevelComplete()` 为 true 时，弹出「本关通过」或直接进入下一关；若还有下一关则显示「下一关」按钮调用 `nextLevel()`，否则进入结束页。

3. **结束页**  
   展示总关数、总找茬数等；按钮「再玩一次」调用 `restart()`。

## 六、点击坐标换算

- 容器使用**固定宽高比**（与设计图一致），或按图片自然比例显示；图片 `object-fit: contain`，避免变形。
- 点击事件取 `e.currentTarget.getBoundingClientRect()` 与 `e.clientX/Y`，换算成图片内部的相对坐标：
  - `cx = (clientX - rect.left - paddingLeft) / imageDisplayWidth`
  - `cy = (clientY - rect.top - paddingTop) / imageDisplayHeight`
- 判定时用「点到圆心距离 ≤ r * 短边」即可（若 r 是相对短边比例，需用当前显示尺寸算出像素半径再比较）。

## 七、资源与关卡

- **美术**：每关需要**左图、右图**两张图（可先使用占位图或 1～2 关示例图）。差异处可以是：多/少一个灭火器、警示牌文字不同、通道被挡等，贴合消防/安全场景。
- **数据**：差异区域坐标可由设计在「标准尺寸图」上标出，再除以宽高得到 0～1 比例写入 `differences`；或先用假数据跑通流程，再替换真实坐标。
- 建议**首版 2～3 关**即可，每关 5 处差异。

## 九、实现顺序建议

1. **数据**：在 `types.ts` 中定义 `DifferenceRegion`、`SpotDifferenceLevel`，并写 1 关 `SPOT_LEVELS`（用占位图 URL + 假坐标）。
2. **Store**：按第三节实现/扩展 gameStore（currentLevelIndex、foundIds、点击判定相关方法）。
3. **双图 + 点击**：在 Game.tsx 中实现左右图展示、点击事件、坐标换算与命中判定、调用 store。
4. **高亮与进度**：已找到的差异在图上绘制圆圈或遮罩，顶部显示「x / 总数」。
5. **过关与多关**：本关完成后「下一关」或「查看结果」，结束页统计信息。
6. **替换资源与坐标**：接入真实图片并填入真实差异坐标，必要时增加关卡。

## 十、可选增强

- **提示**：每关提供 1～2 次「提示」，高亮一处未找到的差异（仅提示，不自动算找到）。
- **计时**：每关或总用时，结束页展示。
- **简单动画**：找到时圆圈放大或勾号动画。
- **音效**：正确/错误点击、过关音效。

按此计划即可将「消防器材总动员」做成大家来找茬玩法；需要按该计划直接改代码时再说即可。
